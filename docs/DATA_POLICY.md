# 数据与生成物管理约定

## 应进入 Git

- Python、MATLAB 和版图转换源代码；
- 中文 README、实验日志、参数清单和结论；
- 小体积配置文件、CSV/JSON 摘要和 SHA256；
- 少量能直接说明结论的关键图片；
- 无法方便重建且体积合理的稳定交付文件。

## 默认不进入 Git

- `artifacts/` 中可重复生成的运行结果；
- 原始相机数据、完整 TIFF、`.bmData`、`.bgData`；
- 大体积 `.npy`、`.npz`、`.mat` 中间数组；
- 调试图、同一结果的 PNG/JPG 重复版本；
- ZIP 归档、Python 缓存和 MATLAB 临时文件；
- 本机编译的 `.mexw64` 等平台相关二进制。

## 稳定基线的保存方式

每个稳定基线至少保留：

1. 来源提交号；
2. 完整配置；
3. 运行命令；
4. 关键指标；
5. 核心输出文件名和 SHA256；
6. 文件存放位置或外部归档位置。

允许把小型最终 BMP/GDS 直接纳入 Git。较大的连续相位和原始数据应使用项目 Release、实验室共享盘或 Git LFS，并在仓库中保留 manifest。不要只在 README 中记录某台电脑的绝对路径。

## 第三方代码

`doe/gdsii-toolbox-master` 属于第三方 GDSII Toolbox。默认不把下载副本和本机 MEX 编译结果直接提交到本项目；优先记录上游地址、版本、安装步骤和许可证，必要时使用子模块。
